# Changelog

## 0.2.8 — model roles and agent persona (C330(4), C322(3), C320, C312a; spec 0.1.69)

- **Cap** `model_roles` in `StatusReport.bridge.caps` (and in re-minted standalone slices): this build implements all of BRIDGE §15 (probe in `caps.test.ts`). Core sends `agents[].persona` and `modelRoleRequirements[]` only to a bridge that declares it.

- **S11 model-role bindings** (`models.sealed.json`, sealed like S3): `{role, ins?, provider, model, baseUrl?, keyName?, dataPolicy, zdrAttestedAt?, dims?}`, workspace default + per-app override, resolve override → default. The key store also holds owner-named provider keys (label ≤ 60) in their OWN namespace (`pk:<label>`, QA-BRIDGE22-1): an app requirement with the same name never reads a provider key (`GET /tb/v1/keys/<name>` serves only requirement keys) and the page shows the two sections apart; a store of the earlier 0.2.8 shape (labels bare in `values`, listed in `providerKeys`) is migrated on load with its bindings (one `keysRev` bump). One key can serve many roles. A requirement (app) key never satisfies a binding (spec 0.1.69): the binding form offers provider keys only, and a stored binding that names anything else (e.g. an app key from the earlier 0.2.8 shape) is not served (resolve `role_not_set`, status `set: false`) and shows "key missing" on the page. Any binding or key change bumps `keysRev` once (wakes `/tb/v1/status` long-polls as before); a crash between the two writes is repaired at boot; older volumes load unchanged; KEK rotation reseals the new record.
- **"Keys and models" page** (same origin, ticket, session, CSRF, CSP, no-redirect rules): Provider keys (write-only, "Serves: role (apps)", deleting a key that serves a model asks first and leaves the binding without a key) and Models (one row per `modelRoleRequirements[]` role; providers from the spec catalog filtered by role, local first; base URL required when the provider has no default; `local` only for a §15.3 URL; `zdr` only for zdrOffered providers with the owner's tick, stored as `zdrAttestedAt`; "Automatic" = `local` for a passing URL; embeddings change warning; per-app override). The model label must match `MODEL_ID_PATTERN` and the provider must be a catalog id; anything else is refused. Ticket `roles[]` hints (at most 8, same patterns) pre-fill for display only. No provider test call. The base URL follows the §15.3 transport rule below.
- **Path errors** (QA-BRIDGE22-2): a malformed percent escape in `/tb/v1/model-roles/<role>` or `/tb/v1/keys/<name>` is `400 bad_request` right after the caller is authenticated (a bad or missing TB-Assert stays 401), never 500.
- **Resolve** `GET /tb/v1/model-roles/<role>` on the internal listener (instance or service assertion): `paused`, `role_not_declared`, `role_not_set`, `role_policy_too_low` (`details {needed, have}`, no binding field), key unset → `role_not_set`; `ModelRoleFetchResponse`, `Cache-Control: no-store`; values never logged. An instance override is used even when it fails the policy (no fall-back to the default). The §15.3 check (spec follow-up #49 at 5676915, text only, never DNS): input hygiene (`\`, `@`, their look-alikes U+FF20/U+FE6B/U+FF3C, `%40`/`%5C` in any case, whitespace, NUL/DEL and other control characters, `?`, `#` refused anywhere), WHATWG parse, http(s) only; the canonical `url.href` is the only form stored and served (`ModelRoleFetchResponse.baseUrl`); host lower-case, one trailing dot removed, Node's bracketed hex IPv4-mapped form decoded BEFORE the checks. NEVER_LOCAL (169.254/16, fe80::/10, fd00:ec2::254, the Alibaba/Oracle/Azure metadata addresses, 0.0.0.0/8, `::`) and NEVER_LOCAL_HOSTNAMES are never local, even when listed. Verified local (`policyBasis: verified`): `localhost`, the exact `.railway.internal` suffix, an origin of `TB_OWN_INFRA_ORIGINS`, 127/8, 10/8, 172.16/12, 192.168/16, `::1`, fc00::/7. Owner-listed local (`owner_attested`, shown as "local (owner-listed, not verified)"): an origin of the owner's Own hosts; tailnet names and CGNAT addresses are local only this way. Transport: `http:` only for a verified host or an owner-listed own-network IP literal; everything else needs https. An `http:` binding whose host stopped being local (env or Own hosts change) is not served: resolve `role_not_set`, status `set: false`. Tested against all 137 rows of the spec fixture (spec 0.1.69, incl. the backslash-only rows) `local-check.cases.json` (copied with placeholders for check-literals). Re-checked at every resolve and status: a stored `local` binding whose URL no longer passes, or a `zdr` binding whose provider no longer offers zdr or has no attestation, counts as `standard`. Error envelopes now carry `BridgeError.details` on the internal listener.
- **Status** `roles[]` `{role, ins, set, policyOk, provider, model, dataPolicy, policyBasis?}`: one row per declared role, labels only; `policyBasis` only when set (`zdr` and owner-listed `local` are `owner_attested`).
- **Own hosts** (spec follow-up #49): a page section, stored in S11 (`ownHosts`, canonical `href`), at most 32 exact http(s) origins (no path); names need https, http only for a private / CGNAT / fc00::/7 IP literal; NEVER_LOCAL refused; a public IPv4 or IPv6 literal is accepted with a warning. Any change bumps `keysRev` once. A removal asks first and names every binding and app that falls below its `minPolicy`; its `local` bindings count as `standard` from the next resolve.
- **Gateway zdr** (spec follow-up #49; effective gateway = `gateway` provider (OpenRouter, LiteLLM, OpenAI-compatible), a provider without a default address, or a base URL other than the default): the attestation is a confirm page that names the host ("I confirm that my contract with <host> keeps no data for every model it routes this role to"); until confirmed, and after a model change, the binding is stored and counts as `standard`. An attestation is kept across saves only for the same provider and base URL (and, for an effective gateway, the same model). Every zdr label reads "zero data retention (owner-attested)".
- **Persona**: a persona over 8,000 UTF-16 units, or one outside `PERSONA_PATTERN` (C356, spec 0.1.69: by Unicode property — refused are \p{Cc}, \p{Cf}, \p{Cs}, \p{Default_Ignorable_Code_Point}, U+2028/2029 except TAB, LF and the marker characters (SHY, CGJ, Arabic number signs U+0600–0605 / U+06DD, ALM, FVS, MVS, ZWSP, ZWNJ, ZWJ, LRM, RLM, variation selectors), and a variation selector directly after a marker; copied verbatim, unicode-mode regex), is dropped for that agent (never cut or cleaned) and counted in `rejected` (`config` / `persona_too_long` or `persona_invalid`). `agents[].persona` leads `initialize.instructions` (outside the 4 KB tools/skills cap), resource `tb://agent/persona` for that agent only, `notifications/resources/list_changed` on change; a paused agent gets only the pause text.
- Pins `@opt2-tealbrick/spec` 0.1.69 (dist release `opt2-tealbrick-specs-spec-v0.1.69`, integrity in the lockfile; the relay keeps its own 0.1.57 through the existing override). Every §15 shape and constant (`MODEL_PROVIDERS` with `gateway`, `NEVER_LOCAL`, `NEVER_LOCAL_HOSTNAMES`, `OWN_HOSTS_MAX`, `POLICY_BASES`, `PERSONA_PATTERN`, `PERSONA_MARKERS`, `ModelRoleStatus.policyBasis`) is imported from the package; there is no local mirror.
- Known gap: `@opt2-tealbrick/manifest` 0.1.30 checks K11 claims as a closed set, so a keys ticket that carries `roles[]` is refused until the manifest package adds the claim; the hint code path is tested below the ticket.
- Tests: `model-roles.test.ts` (RM-2 incl. the 9 policy pairs, RM-3 positives and negatives, RM-4..RM-6, RM-12, bridge half of RM-13 with the spec canaries), `persona.test.ts` (RM-7 incl. 8,000/8,001), `caps.test.ts` probe for `model_roles`, `kek-rotation.test.ts` covers the new record.

## 0.2.7 — app events (C274c/C274d; spec 0.1.57, manifest 0.1.30, conformance 0.1.28)

- **Ingest** `POST /tb/v1/events` on the internal listener (BRIDGE §14.1): instance assertion of the claimed app instance (`htm`, `htu`, `bd`); a companion service → 403; body ≤ 512 KiB, 1..100 items processed in order with one result per item; 429 from the companion-call bucket of the instance; 503 `app_not_claimed` for an instance the config does not list. Per item the §14.1 steps in order (declaration, shape and size, scoped ⇔ `instanceId` + `eligible`, target ⇔ `to`, dedupe of `(app instance, key)` for 7 days, emits and purges alike), with the shared rules of `@opt2-tealbrick/manifest` 0.1.30.
- **Per-agent log** in `node:sqlite` (`<TB_DATA_DIR>/bridge/events.db`; no new npm dependency): ULID ids strictly increasing per bridge (also after a clock step back and a restart), `origin`, the recorded declaration (manifest digest, `visibleWith` op, its scope type), the `eligible` authority, the envelope, ingest time, `held`. Retention per agent: 7 days from ingest or 10 000 rows (oldest by ingest first), `droppedThrough` and a held-row-removed flag answered once as `truncated: true`.
- **Fan-out at write** by MANIFEST §16.2 rules 1–4 (the tools/list rule via `eventVisibleToGrant`, `eligible` with its per-entry authority, never outside it, never to `causedBy`, `to` for target events). **Re-check at delivery** of rules 1, 5 and 6 against the current table and the current serving manifest; pause and G2b waits hold rows, which get new ids (same `origin`, old order) in the same step as the resume or the switch; a rollback drops them. A matching enabled before/after hook strips `summary`.
- **Purges** per agent + instance and for every agent of an instance (delivered or not).
- **MCP**: `tealbrick/events/list`, `tealbrick/events/poll`, `tealbrick/events/stream` on the agent's existing session; `notifications/tealbrick/event` frames on the GET stream with SSE `id:` = event id (no `id:` on other frames), `Last-Event-ID` resume, a second `stream` replaces the subscription and re-sends the backlog; `cursor_invalid` → -32602; paused → `paused: true`. Event reads have their own per-connection rate bucket (20/s, burst 200).
- **Review round 1 (bridge#16):** open event streams are re-authorized (connection active, same `gen` and agent, token not expired) on every config swap and before every flush, and closed at token expiry; a per-app-instance stored-row limit (6 000/min, burst 30 000; 429 / 413 for the whole batch); event-log failures never take the bridge down (corrupt file moved aside, `events` cap only while the log is healthy, ingest 503 / methods -32601 otherwise); counts reset on rollback; drain-aware frame writes; `events/list` skips paused and down instances.
- **Review round 2 (bridge#16):** connection gen and token expiry are per GET stream (a pairing refresh or a Portal rotation closes the old stream and keeps the session and its subscription; a revoke or agent change ends the session); only I/O-class SQLite errors count as unhealthy, with hysteresis for the cap (withdrawn after 5 min, restored after 3 good probes); move-aside only for CORRUPT/NOTADB with a reset point (`truncated` for a cursor below it), any other open failure runs without the log and retries; one drain listener per slow flush.
- **Review round 3 (bridge#16):** the dedupe `keys` table is capped per app instance (100 000, oldest first); the log has a size cap (1 GiB used pages, `TB_EVENTS_MAX_BYTES`) and ingest is refused (503 + Retry-After) when the volume has under 128 MiB free; `events.db`, `-wal` and `-shm` are 0600 and documented as unsealed and part of volume backups; a non-limit ingest failure is logged as `bridge.events.ingest_failed`; `events/poll`, `events/stream` and the live flush fail closed on an expired config (-32000 `config_expired`); ARCHITECTURE section 12 documents WAL on NFS, `synchronous = NORMAL` durability and when a corrupt file is repaired.
- **Cap** `events` in `StatusReport.bridge.caps` (and in re-minted standalone slices), next to `owner_rows`.
- Pins: `@opt2-tealbrick/spec` 0.1.57, `@opt2-tealbrick/manifest` 0.1.30 (also for the relay's validator: a manifest with `events` needs it), conformance 0.1.28, miniapp-sdk 0.1.38 (tests).
